# 用户记忆与隐性接口

文档版本：2026-07-16，对应第四轮独立对话记忆提取。

## 1. 目标

Sumi 不把操作次数、近 7 天或近 30 天的统计直接当作“用户是什么样的人”。

系统只保存能说明来源、适用范围和状态的本地知识。用户随时能看见、修改、停用或删除它；删除后不会再影响建议、检索或对话。

## 2. 四类本地数据

| 类型 | 内容 | 写入方式 | 是否自动用于 Agent |
|---|---|---|---|
| 明确记忆 | 用户明确说明的偏好、目标、约束、纠正 | 独立提取器引用当前原话，或用户在记忆中心添加 | 是，按相关性检索 |
| 当前记忆 | 当前正关注的事项，可关联项目 | 用户明确表达、手动添加 | 是；用户结束或项目删除后停止使用 |
| 隐式记忆 | 用户对首页帮助类别的明确反馈 | 点击、认为不适合、不再推荐 | 达到两次支持且置信度 >= 0.70 后 |
| 原始信号 | 用户对待办和项目的实际操作 | Store mutation 的副作用 | 否；仅供日志、`read_signals` 和未来研究 |

`memory_items` 存记忆本身：类型、分类、内容、项目范围、状态、置信度、来源、替代关系和确认时间。`memory_evidence` 存每条记忆对应的原话、建议反馈、项目状态或历史导入来源。

更新不是字符串相似度合并。新结论如需替换旧结论，必须显式关联旧 ID；旧项会标记为“已替代”，证据仍保留。

## 3. 对话提取和检索

回答 Agent 不再写记忆。每条已保存的普通用户消息会在后台单独经过一次 Flash 判断；回答流不等待它，也不读取 AI 回复、行为信号或完整聊天历史。未来日期的临时会话不提取，因为消息不落库。

提取器输入只有当前消息和最多 3 条已启用的明确记忆候选，输入约 700 token、输出最多 120 token、单次超时 20 秒。它只能返回一个决定：

- `ignore`：没有可长期复用的信息；
- `save`：保存一条明确偏好、目标或约束；
- `replace`：以当前消息明确纠正一条输入候选。

每条消息由 `memory_extraction_runs` 本地记录一次处理结果，应用恢复或重试不会重复提取。无 API Key、超时、模型失败、JSON 无效或本地校验不通过时静默跳过，不影响聊天。

`save` 与 `replace` 必须含当前消息的逐字 `quotedText`、受限分类和简短内容；`replace` 只能引用输入候选 ID。本地会再验证原话、分类、候选状态与长度。相同的已启用明确记忆不重复创建，而是追加原话证据、刷新确认时间；替代在同一事务中把旧项标为“已替代”，保留旧项和旧证据。

自动提取只处理长期明确记忆，不自动提取当前事项。当前事项仍由用户在记忆中心手动添加或明确要求保存。

每轮对话只按当前用户问题检索最多 4 条相关且启用的记忆，不注入整份 `USER_MODEL.md`，也不注入完成率、活跃时段或拖拽率。

`read_memory` 最多返回 8 条紧凑结构化记录，可按项目筛选。回答 Agent 没有 `write_memory` 工具，不能通过工具把行为或猜测写成记忆。

本地语义检索以单条启用记忆建立索引。设备未下载本地模型时，记忆服务仍会用关键词和项目范围做本地检索；普通对话没有匹配记忆时不增加上下文 token。

## 4. 首页建议与信号

首页建议仍用固定本地模板生成。展示、选择和明确否定都记录在 `recommendation_events`；选择和否定会写入对应隐式记忆的证据。未点击不构成反证。

信号仍记录创建、完成、编辑、拖拽和项目参数变更，但信号只是“发生了什么”，不自动变成习惯、人格、能力或计划安排建议。`todoCreated` 继续记录 `source: user/system`。

不再有：

- 每周 Flash 自动归纳；
- `user_hypotheses` 与 `schedule_recommendation_events`；
- “今天新建待办，建议改到明天”的提示；
- 基于固定时间窗的自动用户结论。

## 5. 用户可见性与边界

侧边栏“记忆”打开完整记忆中心，按“正在关注”“你明确告诉我的”“系统从反馈中学到的”“已停用 / 历史导入”展示。用户可以查看来源、添加、编辑、结束当前事项、停用、恢复和删除。

`USER_MODEL.md` 是结构化记忆的兼容导出，不再是系统主数据或编辑入口。旧 Markdown 内容只作为历史导入保存，默认不注入 Agent，用户可在记忆中心确认或重新编辑。

所有信号、记忆、证据、提取运行记录和向量索引都保存在本地 SQLite。首轮不采集设备、位置、通知或跨应用数据；不跨项目泛化；不自动修改待办、项目或计划。
