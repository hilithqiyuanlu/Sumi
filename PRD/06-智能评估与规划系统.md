## 1. 问题与目标

### 1.1 当前问题

05 轮的规划系统本质上是"格式化模板"——给 AI 扔 4 个字段，返回看起来像计划的内容。缺失：

| 缺失环节 | 表现 |
|---------|------|
| **目标质量评估** | 垃圾进垃圾出，用户写"我要学英语"和"我要 3 个月过 IELTS 6.5"得到差不多的输出 |
| **领域知识获取** | AI 凭训练数据记忆编计划，不验证领域真实学习路径 |
| **可行性校验** | 不知道"零基础 + 3 个月 + 每周 6h"学 Rust 到底意味着什么 |
| **外部信息锚定** | 不搜索真实世界的学习资源、路线图、时间线 |

### 1.2 06 轮目标

**做一个"S 级门槛"**——不是一次性做到完美智能，而是搭建正确的架构和流程，让规划从一个 prompt 变成一个有评估→调研→规划→验证的多阶段流水线。后续迭代（07、08…）可以在这个架构上逐步提升智能程度。

### 1.3 设计原则

1. **评估先行，规划在后**——不确定目标质量时，先诊断再开方
2. **外部信息锚定**——搜索真实数据作为规划的地面实况
3. **transparency**——用户能看到 Sumi 在做什么、为什么这么判断
4. **用户始终在回路中**——评估结果可驳回、规划可中止、编辑可回头

### 2.2 关键交互规则

| 规则 | 说明 |
|------|------|
| **目标必填 + 非空判断** | 空目标跳过评估，直接创建空项目（保持 05 行为） |
| **评估在保存时触发** | 用户填写完信息点击"开始评估"→ 进入 Loading 1 |
| **D 级不可通过** | "继续规划"按钮禁用，只能返回编辑 |
| **C 级可强过** | 按钮可用但显示警告文案 |
| **Loading 2 可中止** | 用户点击"停止"→ 丢弃部分结果 → 回到编辑页 |
| **中止后数据不残留** | 部分生成的月卡不入库，只在全部完成后一次性写入 |

## 3. 评估系统设计

### 3.1 评估维度（8 维雷达）

| 维度 | 权重 | 说明 | 低分特征 | 高分特征 |
|------|------|------|---------|---------|
| **清晰度** Clarity | 高 | 目标是否具体、可衡量 | "学好英语" | "6 个月内 IELTS 从 5.5 到 6.5" |
| **可行性** Feasibility | 高 | 在物理/逻辑上是否可能 | "一个月学会脑外科手术" | "3 个月掌握 Python 基础" |
| **挑战匹配度** Challenge Fit | 高 | 目标难度 vs 当前能力的差值 | 零基础 → 职业拳击手 | 有 JS 基础 → 学 TypeScript |
| **可分解性** Decomposability | 中 | 能否拆为递进子目标 | "提升品味" | "学完 CS61A 课程" |
| **时间合理性** Time Realism | 高 | cycleMonths × timeConstraint 是否够 | 3 月 × 3h/周 = 36h 学完微积分 | 6 月 × 10h/周 = 240h 学前端入门 |
| **动机可持续性** Motivation | 中 | 用户多大可能坚持 | "我妈让我学的" | "我想转行做开发" |
| **资源可达性** Resource Access | 低 | 能否获得必要的学习资源 | 需要 10 万实验室设备 | 只需要一台电脑 |
| **进展可测性** Measurability | 中 | 有客观标准判断进度吗 | "理解量子力学" | "通过 AWS SAA 认证考试" |

### 3.2 综合判定规则

```
D 级（不可通过）— 以下任一命中：
  ├─ 物理上不可能（"把太阳射下来"、"永动机"）
  ├─ 无意义/无学习价值（"学好呼吸"、"掌握走路"）
  ├─ 极端困难（当前能力极弱 + 目标极高 + 时间极短）
  │   例：数学小学水平 → 1 个月通过物理竞赛省一等奖
  └─ 不确定性过高（"拿诺贝尔奖"、"成为世界首富"）

C 级（勉强可过，需警告）— 以下任一命中：
  ├─ 至少 3 个维度评分 < 0.4
  ├─ 时间合理性 < 0.3（严重低估所需时间）
  └─ 清晰度 < 0.3（目标过于模糊）

B 级（良好，有改善空间）：
  ├─ 至少 2 个维度评分 < 0.6
  └─ 综合评分 ≥ 0.5

A 级（优秀）：
  └─ 所有高权重维度 ≥ 0.7，综合 ≥ 0.8
```

### 3.3 评估结果数据结构

```dart
class GoalAssessment {
  // 各维度评分 0.0-1.0
  final double clarity;
  final double feasibility;
  final double challengeFit;
  final double decomposability;
  final double timeRealism;
  final double motivationPotential;
  final double resourceAccess;
  final double measurability;

  // 综合判定
  final AssessmentVerdict verdict; // a / b / c / d

  // 诊断信息
  final List<String> concerns;     // 问题点（如"周期偏短"）
  final List<String> suggestions;  // 调整建议（如"建议延长至 6 个月"）
  final String? estimatedHours;    // AI 估算该目标需要的总小时数
  final String? domainSummary;     // 领域知识摘要（搜索获取）

  // 搜索来源
  final List<SearchSnippet> sources; // 评估引用的外部信息
}

enum AssessmentVerdict { a, b, c, d }
```

### 3.4 D 级细分

| 子类型 | 判断标准 | 用户提示示例 |
|--------|---------|------------|
| **impossible** | 物理/逻辑上不可能 | "这个目标在物理上不可行，Sumi 无法为此规划" |
| **meaningless** | 无学习价值/过于简单 | "这个目标不需要专门的学习计划" |
| **extreme** | 能力-目标-时间差距过大 | "以你当前的水平和时间投入，完成这个目标的概率极低" |
| **too_uncertain** | 目标本身不可预测/不确定 | "这个目标的不确定性太高，无法制定有效的学习计划" |

## 4. 两阶段规划架构

### 4.1 阶段 1：评估（Loading 1）

```
输入：goal, level, cycleMonths, timeConstraint
  │
  ├─ Step 1.1: 并行搜索（2-3 个 query）
  │   ├─ search_web("{goal} 学习路线 从零开始")
  │   ├─ search_web("how long to learn {goal} hours")
  │   └─ search_web("{goal} prerequisites beginner")
  │
  ├─ Step 1.2: AI 评估（Flash，无 thinking，快速）
  │   使用专门的评估 prompt
  │   输入：用户信息 + 搜索结果摘要
  │   输出：GoalAssessment JSON
  │
  └─ Step 1.3: 返回诊断结果页
      展示维度评分 + 建议 + 引用来源
```

**评估 prompt 要点**：
- 用搜索结果作为"锚"来判断时间合理性
- 明确区分"AI 不确定"和"确认不可行"
- 给出具体可操作的调整建议，而非泛泛而谈

### 4.2 阶段 2：规划（Loading 2）

```
输入：goal, level, cycleMonths, timeConstraint + GoalAssessment + 搜索结果
  │
  ├─ Step 2.1: 置信度检查（评估阶段是否遗漏信息？）
  │   ├─ 如果领域搜索结果太少/互相矛盾 → 补充搜索
  │   └─ 弹幕："这个领域的信息有点少，让我再搜一下…"
  │
  ├─ Step 2.2: 规划生成（Pro + thinking，重度推理）
  │   增强版 prompt：
  │   ├─ 用户信息
  │   ├─ 评估报告
  │   ├─ 领域知识摘要（搜索结果）
  │   ├─ 认知科学约束（心流/刻意练习/ZPD）
  │   └─ 输出：monthPlans + todayTodos
  │
  ├─ Step 2.3: 规划验证
  │   ├─ 时间数学校验：∑ 每月预估小时 ≤ 总可用小时
  │   ├─ 递进检查：每月核心技能 × 难度系数递进合理
  │   └─ 弹幕反馈验证结果
  │
  └─ Step 2.4: 一次性写入
      全部月卡 + 首日 todo 入库 → 返回项目视图
```

### 4.3 弹幕/气泡机制

**设计目标**：让 Loading 2 不再是死板的进度条，而是让用户感受到 Sumi "在思考"。

**技术方案**：

```dart
// 弹幕消息模型
class PlanningBubble {
  final String text;        // 气泡文本
  final BubbleType type;    // thinking / searching / validating / done
  final DateTime timestamp;
}

enum BubbleType { thinking, searching, validating, info }
```

**触发时机**：

| 事件 | 气泡示例 |
|------|---------|
| 开始搜索 | "让我看看这个领域通常是怎么学的…" |
| 搜索完成 | "找到了几个不错的学习路线参考" |
| 搜索信息不足 | "关于这个方向的信息不太多，我先基于已知的部分来规划" |
| 开始规划 | "根据你的水平和时间，我来设计一个合适的节奏…" |
| 规划第一个月 | "第一个月应该先把基础概念搞扎实" |
| 检测到心流问题 | "等等，第三个月的难度跳得有点大，我调整一下…" |
| 时间校验 | "让我算算，10 小时/周 × 3 个月 = 120 小时，刚好够入门" |
| 完成 | "计划已经生成好了！" |

**UI 表现**：
- 气泡从屏幕下半部分随机 X 位置产生
- 缓慢上浮 + 淡出（约 4-6 秒生命周期）
- 多个气泡可同时存在，位置随机错开
- 不同类型用不同柔和底色区分
- 整体形成一个"弹幕流"的效果

## 7. AI Prompt 设计

### 7.1 评估 Prompt（`_assessmentSystemPrompt`）

```
你是 Sumi，一个专业的自学规划评估师。

你的任务是对用户的学习目标进行多维度评估，给出 A/B/C/D 综合评定。

## 评估维度（每个 0.0-1.0 评分）

1. **清晰度 (clarity)**：目标是否具体、可衡量？
   - 0.0-0.3: 极度模糊（"学好XX"）
   - 0.4-0.6: 有方向但不具体（"提升英语水平"）
   - 0.7-1.0: 具体可衡量（"6个月IELTS从5.5到6.5"）

2. **可行性 (feasibility)**：物理/逻辑上是否可能？
   - D级红线：物理不可能、无学习价值、极端困难、高度不确定
   - 给出具体理由，不要只给分数

3. **挑战匹配度 (challengeFit)**：目标难度 vs 当前能力
   - 参考心流理论：挑战略高于能力时最优
   - 差距过大 → 低分（焦虑区）

4. **可分解性 (decomposability)**：能否拆为递进子目标？
   - 有清晰知识体系 → 高分
   - "提升品味"类 → 低分

5. **时间合理性 (timeRealism)**：周期 × 投入时间是否足够？
   - 用搜索结果中的行业共识作为基准
   - 严重低估 → D级

6. **动机可持续性 (motivationPotential)**：
   - 与用户身份/长期目标是否关联？
   - 首次评估无数据时可给 0.5 默认值

7. **资源可达性 (resourceAccess)**：
   - 是否需要特殊设备/环境/导师？

8. **进展可测性 (measurability)**：
   - 有客观标准（考证/作品）vs 纯主观

## D 级判定（不可通过）

以下任一命中 → verdict: "d"，给出具体理由：
- impossible: 物理/逻辑上不可能
- meaningless: 无学习价值/过于简单
- extreme: 能力-目标-时间差距极大
- too_uncertain: 目标本身不可预测

## 输出格式

严格按以下 JSON：
{
  "clarity": 0.0-1.0,
  "feasibility": 0.0-1.0,
  ...
  "verdict": "a"|"b"|"c"|"d",
  "concerns": ["具体问题1", "具体问题2"],
  "suggestions": ["可操作的调整建议1", "..."],
  "estimatedHours": "约 200-300 小时",
  "domainSummary": "该领域的一小段概述"
}
```

## 附录 A：认知科学理论基础（后续迭代参考）

> 下述理论不需要在 06 轮全部实现，但设计架构时应预留扩展点。

| 理论 | 核心观点 | 对应系统能力 |
|------|---------|------------|
| **心流模型** (Csikszentmihalyi) | 挑战略高于能力时进入心流 | 挑战匹配度评估 + 难度递进曲线 |
| **最近发展区 ZPD** (Vygotsky) | 在有指导时可做到的区间 | 月计划内容必须落在 ZPD 内 |
| **刻意练习** (Ericsson) | 明确目标 + 刚好超出的难度 + 即时反馈 + 重复 | 每日 todo 设计约束 |
| **自我决定理论 SDT** (Deci & Ryan) | 自主性 + 胜任感 + 关联感 | 动机评估 + 规划个性化 |
| **目标设定理论** (Locke & Latham) | 具体 + 有挑战 + 有反馈 | 清晰度 + 可测性评估 |
| **福格行为模型** (Fogg) | B = MAT (动机×能力×提示) | 每日 todo 的粒度控制 |
| **达克效应** (Dunning-Kruger) | 新手高估自己，专家低估自己 | 水平自评的校准追问 |

## 附录 B：D 级判定细则

```
D 级的四个子类型，由 AI 在评估时判定：

impossible（不可能）
  判定标准：违反物理定律、逻辑矛盾
  示例："造永动机"、"把太阳射下来"、"通过意念控制他人"
  用户提示："这个目标在物理上不可行"

meaningless（无意义）
  判定标准：不需要学习就能做到，或"学习"本身没有意义
  示例："学好呼吸"、"掌握走路"、"学会用杯子喝水"
  用户提示："这个技能不需要专门的学习计划，你可能已经掌握了"

extreme（极端困难）
  判定标准：能力极弱 + 目标极高 + 时间极短，概率接近 0
  示例："小学数学水平 → 1个月通过物理竞赛省一等奖"
  判定逻辑：需要同时满足 3 个条件才判 D
    - 能力-目标差距 > 5 个等级（如：入门→世界级）
    - 可用时间 < 行业共识最低时间的 20%
    - 无相关天赋/背景
  用户提示："以你当前的基础和时间投入，这个目标几乎不可能实现。
            建议将周期大幅延长，或先设定一个中间的里程碑目标。"

too_uncertain（不确定性过高）
  判定标准：目标本身的达成不取决于学习，或概率极低且不可控
  示例："拿诺贝尔奖"、"成为世界首富"、"中彩票后如何理财"
  用户提示："这个目标有太多不可控因素，Sumi 无法制定有效的学习计划。
            也许可以拆解为更可控的子目标？"
```
